# EXP-009: Kanban webhook — publish state changes to NATS for agent coordination

## Problem

When an agent moves a kanban item (e.g., to `review`), other agents have no way to
know about it. Today, agents must poll the board. This means PR reviews, handoffs,
and blocked-item notifications require manual coordination.

## Solution

Add a **kanban webhook script** that:

1. Watches for kanban state changes (via git hooks or explicit invocation)
2. Publishes a NATS message on `ship.kanban.{event}` with the item details
3. Agents subscribed to kanban events can automatically pick up review work,
   unblock dependencies, or notify humans via Ships Comm

## NATS Subject Pattern

```
ship.kanban.moved        — item moved to new status
ship.kanban.created      — new item created
ship.kanban.assigned     — item assigned to agent
```

## Message Schema

```json
{
  "type": "kanban_event",
  "event": "moved",
  "item": {
    "id": "EXP-009",
    "title": "Kanban webhook...",
    "status": "review",
    "previousStatus": "in-progress",
    "assignee": "M5",
    "priority": "high"
  },
  "repo": "noesis-ship",
  "timestamp": "2026-02-21T04:30:00Z"
}
```

## Implementation Plan

1. `scripts/kanban-notify.js` — Node.js script that publishes kanban events to NATS
2. Integration with yurtle-kanban via post-move hook or wrapper
3. Agent daemon subscribes to `ship.kanban.>` and can auto-trigger actions
   (e.g., "item moved to review" → spawn `claude -p` to review the PR)

## Use Cases

- **PR review**: Agent moves item to `review` → NATS event → another agent's daemon
  picks it up and runs `/review` on the PR
- **Blocked notifications**: Agent marks item `blocked` → NATS event → Ships Comm
  notifies human via voice: "EXP-009 is blocked, reason: waiting on NATS config"
- **Done celebrations**: Item moved to `done` → broadcast to fleet channel
